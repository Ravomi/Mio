use mio_agent::{run, AgentEvent, Config, Host, HostFuture, Provider, Services};
use std::{path::Path, sync::Arc};

struct ExampleHost;

impl Host for ExampleHost {
    fn shell(&self, _cmd: &str, _cwd: &Path) -> HostFuture<Result<String, String>> {
        Box::pin(async move {
            // 由宿主决定命令执行与子进程实际回收
            Err("未实现 shell 执行".into())
        })
    }

    fn on_event(&self, event: AgentEvent) {
        match event {
            AgentEvent::Text(delta) => print!("{delta}"),
            AgentEvent::ToolStarted { operation, target } => {
                eprintln!("[start] {operation}: {target}");
            }
            AgentEvent::ToolFinished { operation, target, result } => {
                eprintln!("[finish] {operation} ({target}): {:?}", result.is_ok());
            }
        }
    }
}

// 调用入口：mio_agent::run
let updated_history = run(
    config,
    history,
    "查看当前目录",
    &cwd,
    Arc::new(ExampleHost),
    Services::default(),
).await?;
核心设计

直接用，也能成为你应用的一部分

从日常终端任务到自己的桌面界面，复用同一套工具、会话与模型调用逻辑。

Rust 原生进程内集成

以 Rust crate 形式直接链接进宿主程序，共享 Tokio 异步运行时。宿主直接调用 Rust 接口，无需维护额外 Agent 运行进程。

少维护一层： 应用直接调用库；独立使用时，安装一个 Rust 命令行程序即可。

模型与界面自由组合

Mio 核心不捆绑任何特定前端、终端或图形 UI 框架。提供 OpenAI 兼容服务等接入，上层宿主可按需实现任意形式的交互体验。

按项目选择： 连接兼容的云端或本地模型，界面和执行环境由宿主实现。

细粒度结构化事件驱动

整个循环通过强类型的枚举事件驱动，宿主可在第一时间截获 Text 增量、ToolStarted 与 ToolFinished 等结构化事实，精准同步给业务渲染流水线。

过程看得见： 直接消费 Rust 事件或 CLI 的 JSON Lines，展示文本与工具执行进度。

项目上下文与任务一起保留

加载仓库中的 AGENTS.md、项目 Skills 与提示词模板。成功完成任务后，完整消息与工具结果保存为本地会话。

下次接着做： 恢复上次任务，或创建分支尝试其他方案，保留原会话。
当前能力

把日常编码流程连起来

已提供原生 CLI 与 Rust 库。项目仍在早期阶段，以下列出可用功能及后续方向。

能力模块 状态 技术细节与说明
流式内容回复 已具备 模型生成的文本增量以强类型 AgentEvent::Text 事件向宿主实时触发。
多轮工具循环 已具备 自主发起、交替解析与连续处理多轮工具调用，支持多轮历史状态同步。
基础文件读写 已具备 支持文件读取 (read) 与写入 (write)，集成基础工作区相对路径防越界安全检查（非 OS 沙箱）。
宿主命令接入 (Shell) 已具备 通过 Host::shell trait 代理至宿主环境执行，shell 遵循宿主进程权限，宿主可在其实现中加入安全策略与审批。
历史传入与异步取消 已具备 支持宿主传入 Vec<Message> 恢复对话；丢弃（drop）调用 Future 时由宿主负责子进程实际回收。
精确编辑与检索 已具备 edit 只替换唯一匹配；grep、find、ls 支持有界检索与目录查看，读取可按行分页。
工程规范加载 已具备 加载 AGENTS.md、项目 Skills 目录摘要、按需正文与提示词模板；可关闭自动上下文加载。
独立 CLI 交互工具 已具备 单次任务、逐行交互、标准输入与 JSON Lines 事件输出，可配置模型和禁用 Shell。
本地会话与分支 已具备 完整消息与工具结果原子保存，支持列出、恢复和复制分支；模型连接配置不写入会话。
长上下文自动压缩 规划中 长会话的自动摘要与上下文预算管理，当前仍保留完整历史。
完整终端 UI (TUI) 规划中 基于终端的富交互界面、多面板实时渲染与交互式审批组件。
可执行扩展与任务队列 规划中 独立外部进程扩展协议、多任务排队调度与后台异步持久化执行队列。
模型服务接入： CLI 连接支持流式工具调用的 OpenAI 兼容服务，包括兼容的本地模型。库层还提供 Codex、DeepSeek，以及实验性的 Antigravity / DeepSeek 网页适配；CLI 暂不提供 OAuth 登录向导。
开始使用

从一个终端任务开始

准备 Rust 1.95 或更新版本，从源码安装命令行工具。当前尚未发布预编译安装包。

1

安装 Mio

从 GitHub 克隆仓库，使用锁定依赖构建：

git clone https://github.com/Ravomi/Mio.git cd Mio cargo install --path . --locked mio --help
2

连接模型并运行任务

替换下方服务地址、模型名和项目路径，通过环境变量提供 MIO_API_KEY：

export MIO_BASE_URL='https://your-provider.example/v1' export MIO_MODEL='your-model-name' mio --cwd /path/to/project -p '解释项目结构，列出主要模块'

地址和模型名为占位值。兼容的本地免密钥服务可不设置密钥；云服务费用由提供方决定。

3

继续任务，或嵌入你的应用

查看仓库中的集成示例 examples/host.rs，了解如何将 mio-agent 链接至自定义宿主应用、绑定事件流回调与命令执行边界。

使用 mio --cwd /path/to/project --resume 继续最近的会话；加上 --fork 创建分支。更多选项见 README。

使用边界

  • 命令执行： CLI 默认允许文件修改和 Shell，以当前用户权限执行。--no-shell 只关闭 Shell；Unix 原生实现会在取消时终止子进程组。Rust 宿主可复用原生执行模块或实现自己的策略。
  • 文件变动与沙箱边界： Mio 的工作区路径检查可防御相对路径越界，但并非 OS 安全沙箱；工具无审批拦截回调（on_event 仅作通知）；丢弃 Future 取消任务不会自动回滚已写入磁盘的文件，且由宿主负责子进程实际回收。
  • 验证范围： 当前通过 Linux 本地模拟服务、CLI 工作流和子进程测试。其他操作系统与真实账户服务尚未全面验收；完整 TUI、任务队列、双向 RPC 和自动压缩仍未实现。
