Primitives & Capabilities · 核心原语与能力清单

终端即装即用，也可作为你的应用内核。

Mio 不捆绑臃肿的 Web 后台或特定 UI 框架。所有核心能力在 CLI 与 mio-agent Rust 库中完全同构。

Rs

Rust 原生进程内嵌入

桌面应用（如 Ravomi）或后端服务直接通过 Cargo 引入 mio-agent，共享 Tokio 运行时，无需维护跨语言 Sidecar 子进程。

mio_agent::run_with_tools(...)
⇄

结构化事件与双向门控

实时派发 Text、ToolStarted、ToolFinished 枚举事件；宿主可通过 approve_tool 拦截高危操作，或用 poll_steering 在运行中注入纠偏指令。

Host::{shell, on_event, approve_tool}
⚙

细粒度工具过滤策略

支持 --tools 白名单、+tool/-tool 增量调整、--exclude-tools 通配符排除（如 mcp__*）及 --no-tools 纯对话模式。

mio -t read,grep,find -xt bash
⑂

Delegation 结构化适配

提供 DelegationAdapter 统一接口，支持 sync/async 委派模式、独立 runTimeoutMs / waitTimeoutMs 与简洁元数据快照。

mio --subagents --cwd /repo
模块 / 工具 当前状态 工程实现与安全边界说明
read / write ✓ 已具备 UTF-8 分页读取（offset/limit，单次输入上限 8 MiB、输出上限 64 KiB）；原子写入上限 1 MiB。拒绝绝对路径、.. 与符号链接。
edit (精确替换) ✓ 已具备 支持单处 old_text/new_text 或多块不重叠 edits[] 批量替换，拒绝零匹配与多处歧义匹配，保留原文件权限与 CRLF 并输出 Unified Diff。
grep / find / ls ✓ 已具备 grep 支持字面量与有界 Thompson NFA 正则搜索（防 ReDoS）；find 支持子串与 Glob 匹配；自动跳过 .git、target、node_modules，最深 64 层、5000 项上限。
shell / bash ✓ 已具备 由 Host::shell 代理执行非交互命令（120 秒超时，--no-shell 可彻底禁用）。Unix 原生实现会在 Future 取消时终止整个独立子进程组。
subagent (并发子代理) ✓ 已具备 支持 delegate、status（30 秒长轮询）、snapshot、list、kill、fork；最多 4 并发，默认只读，重叠目录自动执行读写互斥锁。
AGENTS.md & Skills ✓ 已具备 按目录层级加载 AGENTS.md 与 .mio/SYSTEM.md；加载 .agents/skills 与 .mio/skills 摘要并支持 --skill、--template。
会话树、导出与压缩 ✓ 已具备 .mio/sessions/*.json 原子保存（0600），支持 --resume、--fork、--name 命名、--export 导出 HTML/Markdown、交互式 /tree 回退与 /compact 压缩。
模型目录、RPC 与 MCP ✓ 已具备 支持 --list-models 模型目录检索、[provider/]model[:thinking] 7 档思考预算、--mode rpc 双向 JSON 协议以及 --mcp Stdio MCP 工具客户端。
全屏富终端 TUI ◎ 规划中 当前 CLI 提供轻量逐行交互（/help、/model、/thinking、/tree、/compact、/export、/fork）、JSONL 与 RPC 模式；多面板富 TUI 界面在规划中。

Design Tradeoffs & Safety Boundaries

我们坚持的极简边界与已知约束

参考 Pi 的原语哲学，Mio 明确区分引擎职责与宿主职责，不伪装未实现的沙箱：

路径防越界 ≠ OS 容器沙箱

checked_path 严格拦截绝对路径、.. 与符号链接，但 Shell 与文件操作仍以当前用户权限运行。生产隔离请结合容器或宿主审批门控。

子进程回收与文件写回滚

Unix 下取消任务会终止独立子进程组；丢弃 Future 不会自动回滚已落盘的文件修改，自定义 Host::shell 需自行负责进程回收。

子代理内存态生命周期

SubagentManager 在进程内维护最多 128 个子会话（单会话上限 2 MiB），主会话离线恢复不会自动重建运行中的子代理实例。

诚实的平台验证范围

已通过 Linux 本地 HTTP 模拟服务、CLI 全流程、并发锁与 Antigravity 真实账号测试；全屏富 TUI 与独立进程扩展协议仍在演进中。

Before You Start · 常见问题

开始前，先说清四件事

会话文件 (.mio/sessions/*.json) 会泄露我的 API 密钥吗？

不会。Mio 在序列化会话快照时绝不写入 Config 中的连接密钥，并在 Unix 下强制设置 0600 权限。但对话历史本身包含读取过的代码片段与提问内容，请按项目敏感数据妥善管理。

只读子代理 (read_only: true) 真的无法修改文件或跑命令吗？

是的。在工具构建与执行双层拦截下，只读工作区不挂载也拒绝执行 write、edit、shell/bash，且不能再次嵌套派生子代理；同时主 Agent 施加的 --no-shell 也会传递约束所有子代理。

如何在不删除既有对话的情况下尝试另一种重构成品？

使用 mio --resume --fork 或在交互模式输入 /fork，Mio 会将当前会话完整克隆到新的时间戳快照文件，并在新分支上继续；或使用 /tree 回退到任意历史轮次。

Mio 与 Rig、Ravomi 以及 Pi 是什么关系？

Mio 从 Ravomi 桌面应用中抽离为独立无头引擎，底层基于 Rig Rust LLM 框架构建，并在上下文工程、会话树与思考档位交互上致敬了 Pi Coding Agent。
