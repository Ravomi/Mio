# Mio 项目审查记录

审查日期：2026-10-15。基线：`60cfb8c82f419e6c3e8320db84c880e3bb19fd46`。范围包括产品层、底层运行契约抽查、CLI/RPC、内置工具、插件/MCP、子代理、上下文、会话、凭据存储、安装发布与 CI。没有修改运行代码、访问真实模型账号或调用付费服务。

这是跨模块审查和离线验证，不是对所有 Provider、平台和可选特性的穷尽证明。新增待办见 [TODO](../../TODO.md)，产品需求与外部调查见 [需求与竞品表](../agent-requirements-and-comparison.md)。

## 结论

现有质量门禁通过，分层已实质存在：`mio-core` 提供模型/协议能力，`mio-agent` 提供通用循环与 hook/bus，产品层提供代码工具、会话与宿主接口。主要短板集中在产品集成：不同工具入口的执行控制不一致、供应商预设超出实际接入协议、外部输出和正则搜索资源边界不足，以及失败回合的持久化执行证据不完整。

应先修执行控制与连接正确性，再做恢复、事件贯通和评测。不能由“Rust 实现”“已有大量测试”“支持多个模型名”推导出更快、更安全或任务成功率更高。

## 证据分类

| 状态 | 含义 |
| --- | --- |
| 已复现 | 在本次构建的 CLI 或库上，用临时目录/本地模拟服务触发并观察到结果 |
| 代码确认 | 代码直接显示当前行为；未进行危险资源耗尽、竞态或线上验证 |
| 条件性风险 | 存在明确机制，需要特定时序或环境；尚未稳定复现 |
| 能力/维护缺口 | 现有边界或产品需求，不等同于已承诺功能的实现 bug |

优先级为修复建议，不是漏洞评分。`P1` 优先处理执行控制、主要连接和可用性，`P2` 随后处理正确性与可靠性。

## 值得保留的实现

- Shell 已有输出截断、超时、Unix 进程组清理及取消测试；插件优先复用这个机制。
- 工作区文件操作有相对路径、父目录导航、静态符号链接及输入/输出上限；这些保障需与竞态、沙箱边界分开描述。
- 会话原子保存、Unix 私有权限、版本检查和大小限制已实现；应补充执行日志，避免推翻已有存储保障。
- 工具调用/结果的安全压缩边界已有测试；改进摘要保真时继续保留这些约束。
- 子代理已有并发上限、默认只读、重叠写工作区拒绝及取消状态；这属于调度保护，仍不是 OS 沙箱。
- 底层已有 provider conformance、hook、effect bus、观察和脱敏能力；先接通产品层，避免重复建设。
