Mio 官方开发指南与系统手册

使用指南涵盖命令行、会话、工具和嵌入接口。示例与参数以当前源码实现为依据。

查看 curl、PowerShell、npm、pnpm、Bun 安装方式

1. 快速安装与模型接入 #

Mio 目前通过 Cargo 进行源码编译安装（Rust 2024 Edition，需 Rust 1.95+）。可直接从 GitHub 仓库克隆构建并在本地环境执行：

bash 
# 源码编译安装到 ~/.cargo/bin
git clone https://github.com/Ravomi/Mio.git
cd Mio
cargo install --path . --locked

# 验证安装
mio --version
⚠️ 模型选择：使用 --model、MIO_MODEL，或导入 Antigravity 配置中的默认模型。
  • 模型选择：使用 --model、MIO_MODEL，或导入 Antigravity 配置中的默认模型。
  • API 密钥：MIO_API_KEY 优先于提供商专属变量；Antigravity 使用独立 OAuth 配置。
  • 思考预算生效范围：思考等级（--thinking 或 model:level 缩写）目前仅在 Antigravity 适配器中消费生效，通用 OpenAI 驱动驱动暂不承诺生效。

多提供商接入范例

bash 
# 1. Google Antigravity 本地 OAuth 凭据 (无感复用，支持思考等级)
mio --provider antigravity --model claude-sonnet-4-5:high -p "审查当前目录代码"

# 2. DeepSeek 官方 API
export DEEPSEEK_API_KEY="sk-..."
mio --provider deepseek --model deepseek-reasoner -p "重构 context.rs"

# 3. 本地 Ollama 离线免密调用
mio --provider ollama --model qwen2.5-coder:32b -p "生成单元测试"

# 4. Anthropic 兼容网关接入 (⚠️ 必须提供 OpenAI 兼容网关)
export MIO_API_KEY="sk-..."
mio --provider anthropic --model claude-sonnet-4-5 \
  --base-url https://your-gateway.example/v1 -p "解释这个架构"

导入已有 Antigravity 配置：mio --import-antigravity ~/.pi/agent。目录需包含 auth.json 与 settings.json，并提供兼容客户端元数据。

2. 交互模式、单次执行与管道标准输入 #

Mio 支持灵活的输入输出管道组合，适应终端人机协作与自动化脚本流程：

  • 交互式终端会话：直接运行 mio。如果在 TTY 终端下未传入提示词，自动进入交互式循环，支持斜杠命令、多轮对话与历史追溯。
  • 单次任务模式 (-p / --print)：运行给定任务后直接退出，适合在构建脚本或 CI 中调用。
  • 管道与非 TTY 标准输入：当通过管道向 mio 喂入输入时，Mio 会自动将 stdin 读取为任务提示词。
  • JSON Lines 流输出 (--json / --mode json)：在标准输出上逐行打印机器可读的 AgentEvent，方便二次包装与前端渲染。
bash 
# 管道输入结合 JSON 流
{ printf '%s\n' '总结本次代码变更的主要风险'; git diff; } | mio --model gpt-4.1 --mode json

3. 会话恢复、分叉与命名导出 #

Mio 的对话与工具执行结果会自动序列化存储在工作区的 .mio/sessions/*.json 目录中（除非显式指定 --no-session）。

🔍 CLI 真实解析事实纠正：--continue 与 --fork
  • -c / --continue 不接受 SELECTOR：-c 或 --continue 仅用于恢复当前工作区最新保存的会话，不消费额外参数。若需按选择器指定会话，请使用 --session <SELECTOR> 或 -r <SELECTOR>。
  • --fork [SELECTOR] 本身合法：--fork 可以单独携带 SELECTOR（如 mio --fork my-feature -p ...），此时会在读取该指定会话的同时自动克隆出全新 UUID 的分支会话，完全保留原会话进度。
  • 参数互斥约束：--resume 与 --session 严格互斥，不能同时传入；--fork 必须搭配 --resume、--session 或自身携带 SELECTOR。
bash 
# 列出当前工作区的所有历史会话（不触碰模型服务）
mio --list-sessions

# 恢复最新会话
mio -c -p "继续刚才的重构"

# 直接分叉指定名称的会话并命名为新实验分支
mio --fork "refactor-phase-1" -n "refactor-phase-2"

# 导出会话记录为单文件独立 HTML 报告
mio --session 9b1f --export ./session-report.html

4. 项目上下文、Skills、模板与 @文件 #

Mio 从祖先目录到当前工作目录加载项目规则，并发现工作区技能与提示模板。

  • 上下文文件：沿祖先目录由根到当前目录加载 AGENTS.md、CLAUDE.md；额外加载当前目录的 .mio/SYSTEM.md。
  • Skills：从 .agents/skills、.mio/skills、.claude/skills 与插件声明中发现技能，通过 --skill NAME 加载。
  • Prompt 模板：.mio/prompts/NAME.md 文件可通过 --template NAME 加载，$ARGUMENTS 会被命令行传入的 Prompt 自动替换。
  • 文件引用：空白分隔且以 @ 开头的 token 可展开 @src/lib.rs 或 @src/lib.rs:10-50。未匹配的普通 @mention 保留原文；显式 @./ 或 @/ 路径不存在、或行范围非法时会报错。
bash 
# 精确携带关键文件片段进行代码审查
mio -p "检查这段逻辑的并发安全隐患： @src/bin/mio.rs:440-480"

# 组合模板执行固定代码检查流程
mio --template review-pr -p "feat(mcp): support dynamic tool registration"

5. 上下文压缩引擎 (Context Compaction) #

💡 DEFAULT_KEEP_RECENT_MESSAGES 与本地结构化摘要
  • 压缩保留约 6 条最近消息，并调整边界以保留完整工具交互；更旧的历史转换成本地抽取摘要。
  • 本地摘要：从旧历史抽取用户意图、工具操作与关键结果，不调用 LLM。摘要可能丢失细节。
  • 自动压缩触发阈值：指定 --auto-compact 时，历史记录超过 512 KiB (DEFAULT_AUTO_COMPACT_BYTES) 就会自动在回合执行前压缩。
text 
# 交互式终端中手动触发压缩，可指定关注焦点
/compact 关注关于 MCP 工具注册与错误处理相关的讨论

# 命令行启动时开启自动压缩
mio --auto-compact -p "大规模批量重构"

6. 原生工具、交互审批与安全边界 #

Mio 原生内置一套经过严格权限与规模约束的代码工具：read（分页读取）、write（创建或全量写入）、edit（单次原子精确定位替换）、grep（正则检索）、find（Glob 文件查找）、ls（目录列举）、bash（命令执行）。

🛑 --approve 交互审批在非 TTY / JSON 下的拒绝行为

当传入 --approve 开启工具确认时，若当前终端为非 TTY 环境或启用了 --json，approve_tool() 无法弹出交互式提示，将直接拒绝所有涉及写入、修改、Shell 或 MCP 的敏感操作并抛出错误（Tool requires interactive approval (--approve)）。绝不会在非交互场景下静默放行危险命令。

bash 
# 禁用 Bash 执行能力（仅保留安全文件读写）
mio --no-shell -p "重命名所有模块导出"

# 精细化工具控制：禁用 bash 和特定工具
mio --exclude-tools "bash,write" -p "搜索项目架构"

# 开启严格交互审批
mio --approve

Shell 在当前用户权限下非交互执行，超时 120 秒。文件工具的路径与输出限制不是操作系统沙箱。

7. 原生子代理委派体系 (Subagents) #

⚙️ 只读默认值与显式可写权限

子代理默认 read_only=true；显式 read_only=false 可允许写入。最多并发 4 个，不继续委派，父回合结束前收集结果。工具权限不是操作系统沙箱。

bash 
# 启动支持子代理的任务执行
mio --subagents -p "让只读子代理检查仓库中的错误处理，汇总发现"

8. 插件生态与 MCP 动态扩展 #

Mio 提供完整的标准插件管理与 Model Context Protocol (MCP) 客户端支持。

⚠️ --no-mcp 会一并阻断插件动态工具

在 src/bin/mio.rs 中，--no-mcp 会直接绕过 load_dynamic_tools() 的执行。而 load_dynamic_tools() 内部同时承担了加载插件内置动态工具（load_plugin_tools）与 MCP 外部工具（load_mcp_specs）的职责。因此传入 --no-mcp 会同时关闭 MCP 服务与插件动态工具。

bash 
# 搜索内置插件注册表
mio --plugin-search github

# 从社区注册表安装插件
mio --plugin-install git-workflow

# 查看当前工作区已安装的插件
mio --plugin-list

9. JSONL 与 RPC 协议模式 (--mode rpc) #

🛑 RPC 运行循环边界与实验性限制
  • 单轮 Turn 阻塞等待：在 run_rpc_loop 中，接收到 prompt 指令后会直接 await runner.turn(&message)。在此期间标准输入的新指令不会并发执行。
  • steer 与 abort 无法实时打断运行中的请求：因为 Turn 执行期间主循环正处于 await 阻塞状态，steer 或 abort 指令无法实时中断正在向模型发送的 HTTP 请求；abort 当前仅返回成功确认 JSON。
  • approve_response 暂无交互接入实现：approve_response 命令接收后仅返回空响应确认，未与底层 approve_tool() 交互渠道打通。外部宿主应标注其为实验性边界。

RPC 指令集一览

10. Rust Host 宿主进程内嵌入 #

Mio 的核心 Agent 循环完全通过 Host trait 解耦，GUI 应用（如 Tauri、Ravomi Desktop）可直接在进程内加载 mio-agent 核心库，无需启动子进程即可实现完全的事件监听与安全拦截：

rust 
use mio_agent::{AgentEvent, Host, HostFuture};
use std::path::Path;

struct ExampleHost;
impl Host for ExampleHost {
    fn shell(&self, _command: &str, _cwd: &Path) -> HostFuture<Result<String, String>> {
        Box::pin(async { Err("Shell is disabled by this host".to_string()) })
    }
    fn on_event(&self, event: AgentEvent) {
        if let AgentEvent::Text(delta) = event {
            print!("{delta}");
        }
    }
}
fn main() {}

/name [TITLE] 可选标题 为当前会话设置易于识别的名字；不传参数时打印当前名字。
/compact [FOCUS] 可选关注焦点 本地摘要压缩，保留约 6 条最近消息并调整工具边界。
/export [PATH] 可选输出路径 将会话完整轨迹导出为独立 HTML 页面文件。
/model [NAME] 可选模型标识 热切换当前使用的模型；不传参数时输出当前模型。
/thinking [LEVEL] off..max 调整思考预算等级（当前由 Antigravity 适配器消费）。
/plugins, /plugin list 无 查看当前工作区已载入的插件清单。
/plugin search [Q] 可选关键词 在线检索官方社区插件注册表。
/subagents 无 查看当前会话已派生的原生子代理运行快照与状态。
/status 无 打印当前会话 ID、模型、提供商、历史消息数及总字节体积。
/clear 无 清除当前终端屏幕。
/exit, /quit 无 退出 Mio 交互式终端。
/plugin installSPEC安装插件。
/plugin removeNAME移除插件。
/plugin initDIR创建插件脚手架。
/plugin validatePATH校验插件目录或注册表。
